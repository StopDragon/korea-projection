# G70 A3000mini USB Wi-Fi 실험 지원

Wi-Fi 부품이 없는 2022 Genesis G70에서 Korea Projection 1.7.4에 USB Wi-Fi를 제공하는 선택형 NEMESIS 보조 패키지입니다. 기본 `korea.projection` 패키지와 USB 빌드는 변경하지 않습니다. 일반 동글 지원을 준비하는 1.8.0의 통합 여부는 별도 검토가 필요합니다.

**화면 연결은 실차에서 확인했지만 음악이 계속 재생되는 동안 화면이 멈추고 반응하지 않는 증상이 남아 있습니다. 안정화된 지원으로 분류하지 않습니다.** 소유자가 멈춘 화면을 종료하려고 연결을 강제로 끊었으므로 로그의 연결 종료를 자연 단절의 증거로 해석하지 않습니다. [실차 검증과 남은 문제](VALIDATION.md)를 먼저 확인하세요.

## 적용 범위

| 항목 | 확인한 값 |
|---|---|
| 차량 | 2022 Genesis G70, `ikfl_kr`, 내장 Wi-Fi 부품 없음 |
| 펌웨어 | `IKFL.KOR.0000.V039.001.260902` |
| SoC / 커널 | `tcc803x` / `3.18.24-tcc` |
| 동글 | ipTIME A3000mini, 실제 USB ID `0bda:b812`, 인터페이스 `ff/ff/ff` |
| 기존 구성 | NEMESIS 1.16.9, HMG-API 1.1.0-rc.7, Korea Projection 1.7.4 |
| AP | 기존 KP 설정의 5 GHz 채널 149 / HT40 / WPA2-CCMP |

제품명만 같아도 USB ID나 커널이 다르면 검증된 장치가 아닙니다. 런타임은 펌웨어·플랫폼·커널·커널 설정 gzip·순정 `bcmdhd.ko`·배포 드라이버의 체크섬을 확인합니다. 이름을 바꾸거나 AP 보완을 수행하기 전에는 실제 네트워크 장치의 드라이버와 USB 인터페이스 modalias, 단일 동글 조건도 확인합니다.

현재의 0.4.1 소스는 실차 0.4.0 코드를 이 저장소 안에서 재현 가능하게 정리하고 USB 선택 검사를 강화한 개발판입니다. 추가 검사는 호스트 시험으로 확인했으며, 0.4.1 전체를 차량에서 다시 실행한 결과는 아직 없습니다.

## 동작

- `g70.usbwifi.bridge`: 부팅 초기에 검증한 `88x2bu.ko`를 등록합니다. 확인한 USB 네트워크 장치만 `wlan0`으로 이름을 바꾸고 HMG-API의 Wi-Fi 존재 표시를 제공합니다. 기존 무선 모드의 검증·설치·적용과 hostapd는 KP가 담당합니다.
- KP DHCP가 살아 있으면 그대로 사용합니다. 없으면 명시적인 사용자·PID/임대 경로와 EOF가 발생하지 않는 FIFO로 네이티브 dnsmasq를 시작합니다. 실제 DHCP 소켓 충돌일 때만 1067/68 포트와 **IP 주소를 보존하는** 포트 변환을 사용합니다.
- AP가 준비됐을 때 정책 표 60/61의 AP 대역 경로가 비어 있으면 해당 경로를 추가합니다. 같은 대역의 기존 경로는 교체하지 않습니다. 자체 경로는 부팅·인터페이스·저장한 내용이 일치할 때만 삭제합니다.
- 실행 중 `rmmod`, USB 강제 리셋, 원본 시스템 파일 교체, 다른 차의 odex 검사 우회는 수행하지 않습니다. 커널 모듈의 USB ID 테이블 자체는 원본과 같으므로 등록된 다른 Realtek 장치에 바인딩할 수 있으나, 이 패키지의 인터페이스 선택과 AP 작업은 위의 확인된 ID/클래스로 제한합니다.
- `g70.usbwifi.logs`: 데이터 포트가 하나인 차에서 현재 기록 저장 → 다음 부팅 드라이버 일시 정지 → USB로 복사 → 다음 부팅 재개를 담당합니다. Bridge의 Launch는 상태 확인용이며 로그 저장 모드로 바꾸지 않습니다.

## 빌드와 호스트 시험

Python 3.9 이상, C 컴파일러 `clang`, `bash`/`dash`/`ksh`를 사용합니다. ARM 드라이버나 차량 명령을 호스트에 적재하지 않으며, 테스트의 파일 시스템과 차량 명령은 임시 디렉터리의 모형입니다.

```sh
python3 experimental/g70-usbwifi/build.py
python3 -m unittest discover -s experimental/g70-usbwifi/tests -p 'test_*.py' -v
```

출력은 `experimental/g70-usbwifi/dist/`이며 Git에는 포함하지 않습니다. 기존 KP 1.7.4를 별도로 설치한 상태에서 사용합니다. 이 빌드는 KP를 재서명하거나 새 버전을 생성하지 않습니다.

수정하지 않은 ARM 상태 클라이언트는 `pkg/bin/ctrl-status`에 있습니다. 대응 MIT-0 소스와 musl/Zig 고지를 `pkg/source/`에 포함합니다. 선택적으로 Zig 0.13.0으로 다시 만들 수 있습니다.

```sh
G70_ZIG=/path/to/zig python3 experimental/g70-usbwifi/build_ctrl.py
```

드라이버의 전체 업스트림 소스 압축, 적용 패치, 차량 설정, 빌드 스크립트와 GPL-2.0 원문은 `pkg/source/driver/`에 있습니다. 드라이버는 실차 파일과 같은 SHA-256으로 고정돼 있습니다. `NOTICE.txt`에 출처와 재배포 구성 요소를 구분했습니다.

## 설치·기록·삭제

바깥 ZIP만 풀고 내용을 USB 최상위에 복사한 뒤 Bridge와 Logs 두 패키지를 설치합니다. 기존 Driver Probe와 충돌하는 다른 USB Wi-Fi 패키지는 메타데이터의 의존성 검사 대상입니다. 동글을 연결하고 내비를 한 번 재부팅한 다음 5분 기다린 뒤 시험합니다. 자세한 포트 하나 운용 절차는 묶음의 `README.txt`에 있습니다.

문제가 나면 추가 재부팅 전에 Logs의 Launch로 기록합니다. 연결 전후, 인터페이스 소실, 부팅 3/5분 상태를 자동 보존하며, 내보내는 로그는 상태·개수·고정 오류 분류입니다. SSID/PSK, MAC/IP, 휴대폰 이름, 위치와 원본 logcat/dmesg·임대 파일은 내보내지 않습니다. 아직 전체 성능 자료와 무선 환경 정보는 충분하지 않아 멈춤의 원인을 확정할 수 없습니다.

삭제할 때는 기록을 먼저 복사하고 Logs → Bridge 순으로 삭제한 뒤 내비를 재부팅합니다. 브리지가 소유한 표시와 규칙을 정리하고 모듈은 재부팅으로 내립니다. HMG-API/KP 무선 모드는 각 패키지의 삭제 절차를 따릅니다.
